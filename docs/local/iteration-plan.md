# omp fork 迭代规划（iteration plan）

> 解决什么：fork 的散点改动是「想到什么改什么」（9-18~9-19 两天内 9 个 commit，无 backlog、
> 无节奏、无复盘）。本文件把改动纳入迭代窗口：**backlog 台账 + 上游 sync 节拍 + 进入门 + 窗口流程**。
> 配套约束见 `fork-divergence.md`（落点分级是强制的）；本文件管**节奏**，不重复落点规则。

## 迭代节拍 = 上游 sync 窗口

fork 的最大成本是 **upstream sync 冲突**（`docs/local/fork-divergence.md` 实测：合并面越大越贵）。
因此把 sync 当作强制 checkpoint，两次 sync 之间就是**一个迭代窗口**：

```
[窗口 N]──────────────────────────[sync N]──[复盘]──[窗口 N+1]────
  选入 1-3 条 backlog            ↑ 强制 checkpoint        backlog 更新
  实现 + 验证                    ↑ 冲突成本实时可见        残差回登
  每条改动独立可合并              ↑ 窗口内改动逐条核验     下窗口选入
```

- **每个窗口只做 backlog 里选定的 1-3 条**，不夹带「顺手的小改」——顺手改正是要防的病。
- **sync 是评估点**：窗口内每条改动在合并时重新核算冲突成本，「成本超预算 → 降级/回退/留在隔离模块」
  由 `fork-divergence.md` 的落点阶梯裁定，本文件只管「这条进不进窗口」。
- **复盘必做**：sync 完成后 `docs/local/iteration-plan.md` 的窗口表追加一行，残差回登 backlog。

## Backlog 台账

在本文档下表维护。候选改动登记时**必须**写全四列（缺列不入台账）：

| 列 | 必填内容 |
|---|---|
| 动机 | 谁要用、解决什么（不是「顺手可以」） |
| 落点层级 | 1 新隔离文件 / 2 设置门 / 3 可选注入 / 4 外科内联（层级定义见 fork-divergence.md） |
| 验证方式 | 一条可跑的测试命令（或明确「手动验证：…」） |
| sync 冲突成本 | 预期：低 / 中 / 高（依据落点层级 + 该文件上游 churn 实测） |

**只登记不实现**：登记 ≠ 承诺。窗口选入时才进入实现。

## 进入门（选入窗口前逐条过，任一不过 → 留 backlog）

1. **动机非顺手**：有人明确要用（自己也会再遇到），不是「改着玩」。
2. **落点已定级**：明确落在 1-4 哪一级；4（外科内联）须附「为什么不能升到 1-3」。
3. **验证可判**：验收有一句能判 pass/fail 的标准（命令输出或手测步骤），不是「看起来对」。
4. **冲突成本可接受**：按落点级 + 上游 churn 估，中或高要写具体依据（不在 sync 时才发现贵）。
5. **一次一改**：一条 backlog = 一件事；多件事拆多条。窗口内改动逐条独立可合并。

## 窗口流程（4 步）

```
1. 选入：窗口首日从 backlog 选 1-3 条过进入门，记本窗口范围
2. 实现：按 fork-divergence.md 落点阶梯实现；一条一 commit（可合并粒度）
3. 验证 + sync 复核：跑该条的验证命令 → sync 时逐条核验冲突成本与落点
4. 复盘：窗口表记一行；残差/新想法回登 backlog（进下窗口的评估池）
```
